How to read this

A charter is the set of terms written down before an agent acts for someone: what it will never do, when it stops, and who answers for it. This report checks whether those terms exist for each agent and whether the platform can hold agents to them. It does not judge whether an agent behaves well. An agent with careful instructions can still misbehave, and one with none may behave perfectly; without written terms, nobody can tell which is which. Everything here was read from your database and configuration; nothing was changed.

Method and limits

What was read. Agent configuration and version history, sharing grants, roles, schedules, Agent API key counts, audit log counts, per-agent conversation counts, librechat.yaml and the plugin's own observer records. Not read: message content, conversation titles, user emails, passwords, tokens, key hashes or action credentials.

Text checks are keyword-based and English-only. Purpose, prohibitions, recipients and the four escalation triggers are found by pattern, carried over from agent-governance-check's codebook where possible. Instructions in other languages read as missing, which overstates gaps; a keyword in an unrelated sentence reads as present, which understates them. Anything found this way is marked “Instructed only”, never “Met”.

Access classes are inferred. LibreChat does not record whether a tool reads, writes or cannot be undone. The class comes from the tool's name, or from the HTTP method in an action's OpenAPI spec. Confirm them in the draft charters.

Approval decisions are simulated from endpoints.agents.toolApproval using LibreChat's own rule order (deny, ask, allow, then mode). Per the v0.8.8 source, that policy is only attached to runs from the chat UI; Agents API and Responses API runs do not get it, while plugin hooks run on every path.

Versions are a lower bound, and deleted agents cannot be checked at all: their configuration is gone.

Charter status. A pass here would mean the written terms exist, not that an agent is safe. The spec says so too: a charter bounds what an agent may touch and makes departures detectable; it does not make a model reliable.
